# 合金冶炼机

中心放置 **熔炼核心**（`alone_mechanical:smelting_core`），正上方紧贴 **合金组件**（`alone_mechanical:alloy_component`），用工程锤右键框选两个相对角点成型。沿用完整长方体外壳、唯一外表面控制器、至少一个能量矩阵的通用构建规则。

恰好需要三个独立的竖向缓存列，端口直接放在各列顶部或底部，并用扳手设定通道：

| 通道 | 缓存 | 用途 |
| --- | --- | --- |
| 输入1 | 物品仓 | 合金主料 |
| 输入2 | 物品仓、流体储罐或气体储罐 | 一种辅料 |
| 输出1 | 物品仓 | 合金产物 |

各列可竖向叠加扩容。输入1固定为主料；添加液体或气体配方时，把输入2的物品仓和端口换成对应储罐与端口，再重新锤定。右键成型结构的任意方块可打开三通道 GUI，物品列每页9槽、独立翻页；液体或气体辅料显示实际罐内容。

最小3×3×3炼钢结构示例（每行从左到右，三层的观察方向一致）：

```text
底层           中层           顶层
入仓 矩阵 辅仓  入1 控制 入2   外壳 外壳 外壳
外壳 外壳 外壳  外壳 核心 外壳  外壳 合金 外壳
出仓 外壳 外壳  出1 外壳 外壳   外壳 外壳 外壳
```

“矩阵”为能量矩阵；三个端口都位于对应仓库上方。能量线圈、效率线圈、处理矩阵和其他合法机器外壳均可替换普通外壳。

## 首批配方：钢

**2 铁粉＋1 碳粉 → 2 钢锭**，基础周期200 tick（20 TPS下10秒），40 FE/t，每份共8000 FE。铁粉放输入1，碳粉放输入2。

- 粗铁在粉碎机中加工：1 粗铁 → 2 铁粉。
- 煤或木炭在粉碎机中加工：1 煤/木炭 → 1 碳粉，100 tick、20 FE/t。
- 配方使用 `forge:dusts/iron` 和 `forge:dusts/carbon` 标签；钢锭加入 `forge:ingots/steel`。
- 每个处理矩阵增加1个并行位和15%耗能倍率，无额外固定数量上限。5个矩阵可同周期加工6份：消耗12铁粉、6碳粉，产出12钢锭；未安装线圈时为420 FE/t。效率线圈每个增加15%速度和10%耗能倍率。
- 原料不足或产物空间不足时暂停。整轮批次固定，完成时再次检查两路输入和输出空间，然后提交资源变更。

## 管道合金

五级管道各自使用一种合金锭。合金机负责制造中间料，之后的烧结、锻压或灌注工序对应各阶段已经解锁的设备和介质：

| 等级 | 合金机工序 | 成锭工序 | 阶段门槛 |
| ---: | --- | --- | --- |
| 1 | 铜粉2＋红石1 → 赤铜混合料2；140 tick，30 FE/t | 熔炉200 tick或高炉100 tick，1∶1烧结赤铜锭 | 粉碎与基础冶炼 |
| 2 | 铁板2＋钢粉1 → 热殷钢坯3；200 tick，50 FE/t | 锻压机：钢坯1→殷钢锭1；100 tick，40 FE/t | 钢、板材与锻压 |
| 3 | 殷钢锭2＋末影珍珠1 → 共振基体2；220 tick，80 FE/t | 灌注机：基体2＋氧气500 mB→共振锭2；180 tick，80 FE/t | 空气分离与气体灌注 |
| 4 | 共振锭2＋钻石粉1 → 超导基体2；260 tick，140 FE/t | 灌注机：基体2＋重水500 mB→超导锭2；240 tick，140 FE/t | 重水与同位素处理 |
| 5 | 超导锭2＋下界合金锭1 → 量子基体2；320 tick，260 FE/t | 灌注机：基体2＋液态钠500 mB→量子锭2；300 tick，240 FE/t | 熔盐电解与核工业 |

赤铜需先将粗铜粉碎为铜粉；殷钢需要先锻造铁板并混合钢粉。共振、超导和量子基体不能直接用于管道配方，必须完成对应灌注。只有后两级消耗液体，合计1000 mB；整条锭产线不消耗任何等级的电解液或维度转换液。

一级管道直接使用赤铜锭，每次制造8个。二至五级管道每次消耗6个上一等级管道、2个本级合金锭和1个阶段辅件，产出6个对应等级管道。三类管道共用同一套等级材料，但物品、流体和气体管道不能互相升级。

## 数据包配方

配方类型为 `alone_mechanical:machine`，机器 ID 为 `alone_mechanical:alloy_smelter`。下面是随模组提供的炼钢配方：

```json
{
  "type": "alone_mechanical:machine",
  "machine": "alone_mechanical:alloy_smelter",
  "item_inputs": [
    { "ingredient": { "tag": "forge:dusts/iron" }, "count": 2 },
    { "ingredient": { "tag": "forge:dusts/carbon" }, "count": 1 }
  ],
  "item_outputs": [{ "item": "alone_mechanical:steel_ingot", "count": 2 }],
  "ticks": 200,
  "energy_per_tick": 40
}
```

物品＋流体时，保留 `item_inputs` 的第一项作为主料，移除第二项，并添加以下字段。`null` 占住输入1的位置，流体实际使用输入2：

```json
"fluid_inputs": [null, { "fluid": "minecraft:water", "amount": 1000 }]
```

物品＋气体使用同样的数组位置：

```json
"gas_inputs": [null, { "gas": "alone_mechanical:hydrogen", "amount": 500 }]
```

这些片段用于说明接口格式；按设计替换介质、数量和产物后放入数据包。一个配方必须有输入1物品、恰好一种输入2辅料和一个输出1物品；非法形状会在加载配方时报错。液体使用 Forge 流体注册 ID；气体使用本模组独立气体 ID 接口。两个输入都按实际并行份数消耗。

## 验证入口

`AlloySmelterGameTests` 覆盖炼钢实际比例与耗能、缺料和堵塞保护、32份加工存档恢复、物品＋流体/气体运行与配方网络往返、三个物品通道分页、非法输入拒绝及煤/木炭制碳。

```powershell
./tools/verify_alloy_resources.ps1
./gradlew.bat --offline runGameTestServer build
```

资源脚本只验证资源结构与引用。Java 编译和游戏行为需要实际执行 Gradle 检查确认。

当前成型必须在中心熔炼核心正上方紧贴合金组件；最小结构中组件占顶部中心格，完整规则见 [machine-components.md](machine-components.md)。
