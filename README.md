# 孤独机械 · Alone Mechanical

Minecraft **1.20.1 / Forge 47.4.27 / Java 17**。

当前科技线：[主干、产线、回收及断点总览（2026-10-20）](docs/current-technology-tree.md) · [正式配方清单](docs/technology-recipes.md)。按现有资源整理，不恢复已移除的机器方块合成配方。

工程按照[参考教程第 1–4 章](https://www.mcmod.cn/post/6071.html)整理：主类只负责模块初始化，`init` 集中注册方块、物品、创造栏、方块实体、菜单和配方；`registerBlock` 自动注册 BlockItem，`registerItem` 接收物品工厂；资源包含模型、方块状态、中英翻译、掉落和标签。保留原项目的包名和 mod id。

创造栏为 **孤独机械 · 方块 / 孤独机械 · 物品 / 孤独机械 · 杂项**。现有方块和物品使用 Codex 按功能绘制的原创 **16×16** 像素材质；管道及接头材质为原生 **8×8**。能量矩阵绘制电池组、线圈绘制绕组和转子、储罐绘制观察窗，粉末按材料着色。通用端口正面显示模式箭头和通道标记。运行 `tools/generate_resources.ps1` 可重绘全部资源，`tools/preview_mod_textures.ps1` 可生成材质总览和玻璃衔接预览。

## 教程书

教程书位于“孤独机械 · 杂项”，用 **一本原版书 + 一个铁粒**无序合成。手持右键空中或方块打开教学面板；空主手时副手教程书也可打开。十二章包括入门、电网、多方块构建、物品加工机器、电动泵、双相反应釜、三相分离、气液转化机、仓储与端口、管道、升级与 GUI 排查，中英文自动分页。点击目录、翻页按钮，或用滚轮、方向键及 PageUp / PageDown 阅读；Esc 关闭。电网范围、构建尺寸、电池基础容量和升级上限读取当前配置或实现常量，具体配方以当前世界 JEI 为准。

教程内容由 `tools/generate_tutorial_resources.ps1` 维护，资源生成会同步中英文文本和合成配方。客户端验证使用独立测试世界：准备 `tools/prepare_machine_gui_test_world.ps1` 后执行 `./gradlew.bat --offline -I tools/tutorial-client-check.gradle runClient`，会逐页检查两个语言版本，生成 `build/tutorial-preview.png` 等截图后自动退出。成功日志包含 `TUTORIAL CLIENT CHECK PASSED`。

所有本模组物品和方块统一使用 Shift 说明：默认只显示“按住 [Shift] 显示功能和信息”，按住后展示用途、参数、操作方法和限制，包含工具、材料、核心、机器部件、仓储、电网和十五种管道。中英说明由 `tools/generate_item_descriptions.ps1` 维护；`tools/generate_resources.ps1 -HelpOnly` 只更新教程与提示文本。

## 单方块电动泵

**电动泵**放在液体源正上方即可使用，无需多方块或工程锤。每轮只抽紧贴底面的一个可汲取液体源；水/岩浆为1000 mB，基础20 tick、40 FE/t，内部缓存16000 mB。普通流动液体不会抽取，水浸方块按桶取水规则排水并保留原方块。支持供电桩覆盖和任意面直接输入FE。

右键GUI安装升级方块：**效率线圈最多8个、能量线圈最多8个、能量矩阵最多64个**。沿用速度、加法节能与电池扩容规则；变更升级重置当前进度，移除矩阵按新容量裁剪电量。上方或侧面接流体管道，源端设为拉取；底面只用于世界抽液。满罐、混液、无源或缺电时停机。升级方块可取回，拆泵时也会掉落已安装升级。原生16×16外观包含底部抽取口、顶部出液口和运行指示灯。

详细说明见 [docs/electric-pump.md](docs/electric-pump.md)。资源检查使用 `tools/verify_pump_resources.ps1`，服务端测试为 `ElectricPumpGameTests`，客户端检查使用 `tools/pump-client-check.gradle`，生成空槽与安装升级后的实际GUI截图。

## 三相分离器

使用**反应核心＋正上方分解组件**，用于一路输入、两路输出的独立分解配方。结构恰好三列仓储：**输入1、输出1、输出2**，端口紧贴各列顶部或底部。物品/流体/气体仓储组合决定18种类型，例如固相分选、热解分离、液液分离、脱气分离、电解分离和气体分离。GUI显示一进两出，两个输出禁止放入物品并可独立翻页；任一路堵塞都会暂停整轮加工。

首个正式配方为**水电解：1000 mB水 → 1000 mB氢气＋500 mB氧气**，200 tick、60 FE/t，氢氧比2∶1。输入1为水罐，输出1/2为独立气罐；通用储罐的空输出会按匹配配方准备气体介质。沿用线圈、电池和最多32份并行。配方单独注册，不从双相反应釜推导逆向配方。分解组件使用原创16×16材质，中英文名称、JEI分类与教程书章节同步加入。

全部类型及数据包格式见 [docs/three-phase-separator.md](docs/three-phase-separator.md)。资源检查：`./tools/verify_separator_resources.ps1`；客户端检查：先执行 `./tools/prepare_separator_test_world.ps1`，再运行 `./gradlew.bat --offline -I tools/separator-client-check.gradle runClient`，使用独立复制存档并在检查18种GUI、JEI、气体名称与教程后自动退出。服务端用 `SeparatorGameTests` 覆盖独立配方、两路输出、物理仓储、分页、并行和存档恢复。

## 合金冶炼机

中心放**熔炼核心**，正上方紧贴**合金组件**，设置三个独立缓存列：**输入1物品仓、输入2物品仓/流体储罐/气体储罐、输出1物品仓**。匹配端口紧贴各列顶部或底部，扳手设定通道；外表面保留一个控制器及至少一个能量矩阵，工程锤框选成型。GUI 显示两个输入和一个输出，物品列独立分页，辅料罐显示实际介质与容量。

首个正式合金配方为 **2 铁粉＋1 碳粉 → 2 钢锭**，基础200 tick、40 FE/t。煤或木炭可在粉碎机中制成碳粉（1→1，100 tick、20 FE/t），铁粉由粗铁粉碎获得。效率线圈每个增加15%速度和10%耗能倍率；处理矩阵每个增加1个并行位和15%耗能倍率，无额外固定数量上限。合金组件、碳粉、钢锭具有原创16×16材质，教程书和JEI同步提供说明与配方。三种辅料输入的结构、最小搭建示意和数据包格式见 [docs/alloy-smelter.md](docs/alloy-smelter.md)。

本次合金功能的资源结构检查可运行 `./tools/verify_alloy_resources.ps1`；Java GameTest 入口为 `AlloySmelterGameTests`，需通过 Gradle 执行后才能确认运行结果。

## 电网

新增**屠杀组件、养殖组件、收割组件、驱逐组件**：紧贴工业核心正上方，分别构成**屠宰器、养殖塔、收割塔、驱逐塔**。这四种机器长宽必须为**3×3**，高度为3至配置上限，仍需完整外壳、唯一控制器、至少一个能量矩阵。必须有**输出1物品仓及其上下相邻通用端口**；养殖塔另需独立**输入1食物仓**。失败时工程锤显示对应原因。

范围默认以核心为中心，水平半径8格、上下各4格，即**17×9×17**；GUI显示实际尺寸。佩戴**工程师眼镜**，按住**Shift**对准成型机器的部件，可查看半透明红色范围框；松开Shift隐藏。参数为`fieldMachineRadius`、`fieldMachineVerticalRadius`、`fieldMachineFEPerTick`（默认20 FE/t）、`breedingTowerAnimalLimit`（默认单类64只）。范围内只处理已加载区块。

- 屠宰器：GUI左右切换生物类型，添加/移除白名单；默认不攻击，永不攻击玩家或已驯服宠物。基础每秒对一个指定目标造成8点伤害；战利品进入输出仓，溢出内容暂存并保存，等待输出空间后再继续攻击。
- 养殖塔：从输入仓消耗两份匹配的繁殖食物，繁殖一对成年动物；保留原版冷却和幼年成长规则，达到数量上限时停止繁殖。
- 收割塔：支持CropBlock作物、下界疣、可可与甜浆果；成熟后获取一次正常产物并重置生长。需重种的作物预留一个种植物，满仓不重置作物。
- 驱逐塔：供电并保持结构完整时，阻止范围内敌对生物自然/刷怪笼刷新；不清除已有生物，也不阻止被动动物。断电或损坏后停止保护。

四种机器沿用当前加成：效率线圈加快作业周期；处理矩阵增加每轮处理目标/作物/动物对数量；能量线圈影响耗能；能量矩阵扩容；强化外壳提供原有保护。基础周期20 tick，处理矩阵及线圈按现有机器公式计算耗能。驱逐塔持续消耗FE维持保护。

屠宰器与养殖塔均支持**每种生物独立数量配置**：左右切换类型，输入数量并保存，可单独启用/停用。屠宰器的数量是“至少保留”：例如牛设10只，只有范围内超过10只才攻击，处理矩阵也不能越过保留线。默认保留0只且未启用任何目标。养殖塔的数量是“繁殖上限”：例如牛设10只，范围内牛（含幼年）达到10只后不再消耗食物，猪的设置独立。养殖塔默认启用可繁殖动物，单类上限默认读取配置；GUI点击“按种类配置数量”切换设置页，点击“返回食物输入仓”恢复库存视图。数量与启用状态随机器保存，不同种类互不占用数量配额，未单独设置时读取`breedingTowerAnimalLimit`的默认值。

生存发电可使用**基础光能发电机、夜光发电机、热能发电机**，放在电网核心旁即可供电，或直接连接兼容FE的机器输入端。三种设备均有100,000 FE缓存、六面FE输出和右键状态界面；光能机顶部需露天，太阳能板沿东西方向追踪太阳，夜晚转向月亮。基础光能机夜间停止，夜光机昼夜持续发电，不受月相和雨天影响。默认基础/夜光为320/240 FE/t。

热能机接受煤炭、木炭、煤炭块，以及五种**一次性电池**；支持物品管道、漏斗和Shift搬运。煤类按原版燃烧时长供电，默认40 FE/t。一次点燃一件燃料，持续供电直至烧尽，不返回空电池；缓存不足以容纳下一tick电量时暂停燃烧，不浪费剩余时长。移除方块会掉落排队燃料，已点燃燃料及内部电量不保留。

| 电池 | 默认发电量 | 默认燃烧时长 | 相对高级标准电池 |
| --- | --- | --- | --- |
| 初级 | 80 FE/t | 3,200 tick（160秒） | — |
| 中级 | 160 FE/t | 6,400 tick（320秒） | — |
| 高级 | 320 FE/t | 12,800 tick（640秒） | 1倍功率、1倍时长 |
| 高级·高功率 | 480 FE/t | 8,960 tick（448秒） | 1.5倍功率、0.7倍时长 |
| 高级·长续航 | 320 FE/t | 19,200 tick（960秒） | 1倍功率、1.5倍时长 |

发电机保留生存合成配方，五种电池暂不提供默认配方；按Shift查看当前配置下的功率与时长。存档服务器配置新增`solarGenerationFE`、`lunarGenerationFE`、`coalGenerationFE`、`basicBatteryGenerationFE`、`basicBatteryBurnTicks`，电池等级与变种从初级参数计算。正在燃烧的一件燃料保存点燃时的功率/时长，重载不会重置或重复消耗。

1. 放置一个电网核心、若干信号杆和供电桩。杆与桩占据 **1×1×5** 个真实方块，核心占 **1×1×1**。
2. 右键节点任意一段打开电网 GUI，点击**开始连线**，界面关闭后右键目标节点任意一段完成连接。对已连接的两个节点重复操作可断线；潜行右键节点取消起点，也可以再次右键起点打开 GUI 点击**取消连线**。选择在切换维度、退出游戏或 10 分钟后失效。
3. 信号杆最大连接 **80 格**，供电桩最大连接 **60 格**。两端限制取较小值，距离为三维直线距离，核心按 80 格计算。
4. 电网允许一个核心。无核心的节点可先连线；直接或间接合并两个有核心的电网会被拒绝，未加载节点同样计入这个限制。
5. 核心储能默认 **1,000,000 FE**，支持 Forge Energy 输入，也会从相邻方块抽取 FE。生存时把光能/热能发电机或外部FE电源放在核心旁边；创造测试可使用“杂项”中的**创造电源**。
6. 供电桩以底座为中心，水平 **15×15**、高度上下各 **5 格**为供电区域，以机器工业核心的位置判断覆盖。成型机器从电网核心充入自身电池，加工从机器电池扣电；多个桩覆盖同一机器不会重复充电或扣费。断网后可使用剩余电量继续加工。

连线出现在节点顶部，绿色表示连接路径有电，红色表示无电，状态最多延迟 10 tick 更新。右键节点打开电网 GUI。拆掉杆体任意一段会移除整杆；玩家破坏仅掉落一件。连线按维度保存，不强制加载区块，只有已加载的连通路径可供电。

参数位于存档 `serverconfig/alone_mechanical-server.toml`：`coreCapacityFE`、`machineBatteryCapacityFE`、`machineChargeRateFE`、`signalPoleRange`、`powerPylonRange`、`supplyRadius`、`supplyVerticalRadius`、`maxMachineCubeSize`（沿用原配置名，现在限制长方体每一轴的最大长度）。

## 粉碎机多方块

结构是由工程锤确定范围的**长方体**，长、宽、高各自允许 **3–16 格**，三边可以不同，上限可配置。

1. 搭建长方体完整外表面，使用机器外壳类型方块；外表面任意位置放**恰好一个通用机器控制器**。
2. 选区内必须恰好有一个**工业核心**，可放内部或外表面，不必位于几何中心。机型组件只能有一个，必须紧贴实际工业核心正上方，并包含在选区内。各机器使用对应组件选型；核反应堆沿用同高四周燃料棒。内部其他位置可放空气或合法机器部件。
3. 放置至少两个**独立物品仓整体**，通用物品端口放在对应仓库列的顶部或底部，一个端口设为**输入1**，另一个独立仓的端口设为**输出1**，每侧至少 27 槽；上下相连的仓库算同一个整体。再放置至少一个**能量矩阵（能量模块）**。
4. 手持**工程锤**，右键两个相对角点。两个端点都包含在选区中，系统检测整个范围，检查形状、外壳完整性、工业核心、控制器、成员归属及缓存边界，全部通过后成型。
5. **Shift 右键方块或空气取消选点**。检测失败显示**构建失败：原因**，方块问题附带坐标；未知结构和缺失部件也会说明原因。构建异常停止成型并记录服务器日志。失败保留第一个角点，可修复后重新选择第二点。机器不会靠普通右键或等待自动成型；结构修复后用工程锤重新检测。

选区不能和另一台成型机器重叠，竖向缓存整体不能跨出机器边界。已成型机器的范围和归属保存到存档，重新加载时恢复检测。

| 外层部件 | 效果 |
| --- | --- |
| 机器外壳 | 基础结构 |
| 强化外壳 | 自身防爆；成型结构含强化外壳时保护整台机器免于爆炸拆毁 |
| 能量线圈 | 每个从基础耗能倍率减去 20 个百分点，单份最低 1 FE/t |
| 效率线圈 | 每个速度增加 15%、基础耗能倍率增加 10 个百分点 |
| 能量矩阵 | 每个增加基础电池容量的 100%，多个线性叠加；成型后还可作为 Forge Energy 输入端 |
| 处理矩阵 | 每个增加 1 个并行位、基础耗能倍率增加 15 个百分点，无额外数量上限 |
| 结构玻璃 | 中心透明、透光，相邻玻璃自动消除内部边框，保留外缘与凹角；六个面都支持连接 |
| 通用物品 / 流体 / 气体输入输出口 | 连接外部自动化，独立选择通道 |
| 流体储罐 / 气体储罐 / 物品仓 | 可用于外表面或内部，扩展机器对应通道的缓存 |

最终耗能倍率为 `max(0, 1 − 0.20 × 能量线圈数 + 0.10 × 效率线圈数 + 0.15 × 处理矩阵数)`。所有加成先按基础值相加减，单份每 tick 向上取整且至少消耗 **1 FE**，最后乘实际加工份数；速度为 `100% + 15% × 效率线圈数`。例如一只能量线圈、一只效率线圈和两只处理矩阵的倍率为120%，三份基础20 FE/t的配方共消耗72 FE/t。

机器基础电池默认 **100,000 FE**，总容量为 `基础容量 × (1 + 能量矩阵数量)`，例如 1/2/3 个矩阵对应 **200,000 / 300,000 / 400,000 FE**。容量受 Forge 整数接口限制，最高 2,147,483,647 FE。成型后即使空闲也会从覆盖电网充电，默认每 tick 最多 **10,000 FE**；控制器和成型能量矩阵支持外部 Forge Energy 输入，不向外输出。电池电量保存在控制器 NBT；拆除矩阵后重构机器时，超出新容量的电量会被裁掉。

**处理矩阵**属于机器外壳，支持放在选区外表面或内部。无矩阵时每轮处理 1 份配方，每个处理矩阵增加1份并行能力；粉碎机、电弧炉及数据包机器配方均可使用。每轮开始时按全部原料和输出空间选择可执行的份数，原料不足时可执行小批量；选定份数在整轮内固定，中途增加原料不会放大已付费的批次。加工时长保持单份时长，物品、流体和气体的消耗与产物按实际份数同比增加，耗能为 `单份线圈修正后耗能 × 实际份数`。例如两个处理矩阵允许三份粗铁在同一个100 tick周期内产出6铁粉；不加其他线圈时，每份基础20 FE/t增加30%后为26 FE/t，整批78 FE/t。输出空间被占用时暂停，不继续扣电，空间恢复后继续。批次份数随进度保存，旧存档默认单份。

手持**机械扳手**右键通用输入输出口，循环切换 **输入1 → 输入2 → 输出1 → 输出2**。端口模式独立保存，仓库本身不设置输入输出模式。输入只接受资源，输出只允许外部提取；四种模式分别映射到机器对应通道。物品通道完全使用实体仓库，双相反应釜、三相分离器、气液转换机与合金冶炼机的液体和气体通道完全使用实体储罐；粉碎机与电弧炉保留每通道 **16,000 mB** 液体／气体暂存区。正面蓝色箭头指向托盘表示输入，橙色箭头离开托盘表示输出，下方一个／两个点表示通道1／2；切换后立即更新并保存。

**空手普通右键成型结构中的任意外壳、接口、储罐、物品仓、控制器或工业核心，都会打开同一机器 GUI**，按每页27槽操作输入1与输出1的全部物品仓库存，并查看加工进度、耗能、线圈、电池电量/容量和矩阵数量。界面显示每侧总槽数，输入和输出分别翻页；外壳和结构内部的同通道物品仓全部计入，Shift搬运会使用整个输入库存的空位。手持方块时优先在点击面放置方块，无需按 Shift；机器成型前后及独立缓存均适用。即使点击点远离控制器，也以实际点击位置判断打开距离。损坏结构停止加工、断开机器接口并关闭无效菜单。

当前提供三条粉碎配方：粗铁、粗铜、粗金各 1 个产出对应粉末 2 个，支持原版粗矿及对应 `forge:raw_materials/<metal>` 标签。基础耗时 100 tick（5 秒），耗能 20 FE/t（共 2,000 FE），JEI 显示原料、产量和加工成本。粗材料、粗材料块及加工材料已移除。另提供煤/木炭制碳、铁粉与碳粉炼钢、水电解制氢氧三条独立配方；粉末熔炼及其他进阶配方由数据包补充。现有方块与物品可从创造栏或 JEI 取得用于测试。电弧炉由**工业核心＋正上方煅烧组件**搭配物品仓构成，仍兼容外部原版、数据包及其他模组的 `minecraft:smelting` 配方；这项适配不新增原版或模组配方。核心家族与机器 ID 分开注册，后续可在同一工业核心下新增储罐类型配置。没有匹配配方时机器保持空闲，不消耗原料与加工电力。

## 气液转换机

工业核心正上方放置**气液转换组件**，外壳、单个控制器和至少一个能量矩阵沿用其他机器的要求。需要**一个独立流体储罐列和一个独立气体储罐列**，对应通用流体／气体端口放在各列顶部或底部，分别设为**输入1、输出1**；不需要物品仓，竖向叠罐扩容，每段 **16,000 mB**。工程锤检测通过后打开 GUI：

- **液化：气体 → 液体**，气体端口输入，流体端口输出。
- **气化：液体 → 气体**，流体端口输入，气体端口输出。

GUI 选择由服务端校验，并自动反转所有相应端口。切换清除本轮进度、加工批次和运行状态，保留储罐内容及剩余电量；已消耗的加工电量不返还。模式及加工进度随存档保存。机器实际加工直接读写实体储罐，不附加控制器暂存容量；支持电网、线圈和处理矩阵。输出空间不足或介质不匹配时暂停，不消耗输入或加工电量。

JEI 显示转换核心用途和已加载配方。具体气液配对、转换比例、耗时及耗能由数据包定义，正式资源不注册测试用转换配方。配方类型为 `alone_mechanical:machine`，机器 ID 为 `alone_mechanical:gas_liquid_converter`，`conversion` 必须为 `gas_to_liquid` 或 `liquid_to_gas`；只使用输入1、输出1。例如液化格式：

```json
{
  "type": "alone_mechanical:machine",
  "machine": "alone_mechanical:gas_liquid_converter",
  "conversion": "gas_to_liquid",
  "gas_inputs": [{"gas": "your_pack:gas_id", "amount": 1000}],
  "fluid_outputs": [{"fluid": "minecraft:water", "amount": 1000}],
  "ticks": 100,
  "energy_per_tick": 20
}
```

气化使用 `conversion: "liquid_to_gas"`、`fluid_inputs` 和 `gas_outputs`。气体仍使用本模组独立气体能力，不将液体注册表内容自动视作气体。

## 双相反应釜

使用**工业核心＋正上方化合组件**，保留完整长方体外壳、一个外表面控制器及至少一个能量矩阵。成型需要**恰好三个独立仓储列**，使用物品仓、流体储罐或气体储罐；各列顶部或底部紧贴对应类型的通用端口，分别设置为**输入1、输入2、输出1**。仓储的输入和输出类型决定模式，两个输入可以交换端口通道。竖向叠仓算一个整体，第四列、重复输入通道、输出2及侧面端口均无法成型。

| 模式 | 两个输入 → 输出 | 数据包机器 ID |
| --- | --- | --- |
| 溶出制液 | 物品 + 液体 → 液体 | `alone_mechanical:dissolution` |
| 溶解析晶 | 物品 + 液体 → 物品 | `alone_mechanical:crystallization` |
| 液相捕收 | 液体 + 气体 → 液体 | `alone_mechanical:liquid_capture` |
| 液相生气 | 液体 + 气体 → 气体 | `alone_mechanical:gas_evolution` |
| 气固相炼 | 物品 + 气体 → 物品 | `alone_mechanical:gas_solid_refining` |
| 固转气化 | 物品 + 气体 → 气体 | `alone_mechanical:solid_gasification` |
| 液相合制 | 液体 + 液体 → 液体 | `alone_mechanical:liquid_reactor` |
| 气相化合 | 气体 + 气体 → 气体 | `alone_mechanical:gas_reactor` |
| 固相熔合 | 物品 + 物品 → 物品 | `alone_mechanical:solid_fusion` |

资源直接保存在实体仓储，每段物品仓 **27 槽**，流体／气体储罐 **16,000 mB**，反应釜不添加控制器暂存容量。支持电网、线圈和处理矩阵。GUI 分别显示输入1、输入2、输出1；物品仓每页9槽独立翻页，液体显示真实纹理与液位，气体显示种类和容量。工程锤选第一个角点后，手持时显示青色范围框、橙色起点及尺寸；第二次点击检测，聊天栏和动作栏显示成型模式、三个仓储通道或失败原因。

配方类型为 `alone_mechanical:machine`。输入数组按表中列出的顺序填写，未使用的资源位置用 `null` 或 `{}` 占位；不同资源的两个实体输入仓交换通道时，机器自动匹配到配方顺序。输出数组第一项对应输出1。例如溶出制液的配方形状如下（仅说明格式，不作为正式配方注册）：

```json
{
  "type": "alone_mechanical:machine",
  "machine": "alone_mechanical:dissolution",
  "item_inputs": [{"ingredient": {"item": "minecraft:stone"}, "count": 1}, null],
  "fluid_inputs": [null, {"fluid": "minecraft:water", "amount": 1000}],
  "fluid_outputs": [{"fluid": "minecraft:water", "amount": 1000}],
  "ticks": 100,
  "energy_per_tick": 20
}
```

正式反应配方由数据包提供；九种模式的验证代码及测试探针不进入发布 jar。JEI 为每个模式提供独立分类，共用工业核心与化合组件查询。

## 竖向储罐与物品仓

机器 GUI 使用紧凑的 **358×232** 布局：顶部为独立翻页的输入和输出库存，中间显示加工进度，下方左侧为运行状态／流体气体缓存页签，右侧为玩家背包。输入使用青绿色、输出使用金色框，状态栏区分加工中、等待原料、电量不足和输出空间不足；电量条和进度条显示实际同步数据。耗能、电池、线圈和缓存数值可悬停查看完整详情，大数使用简写，避免文字挤出面板。

GUI 客户端验证：在服务端测试退出后运行 `./tools/prepare_machine_gui_test_world.ps1`，再运行 `./gradlew.bat --offline -I tools/machine-gui-client-check.gradle runClient`。使用独立测试世界和客户端演示数据，检查 90 个槽位边界、分页按钮及缓存页签，保存实际 GUI 截图到 `build/machine-gui-preview.png` 和 `build/machine-gui-cache-preview.png` 后自动退出。成功日志包含 `MACHINE GUI CLIENT CHECK PASSED`，测试代码不进入发布 jar。

| 方块 | 每段容量 | 竖向连接效果 |
| --- | --- | --- |
| 储罐 | 16,000 mB | 同列只存一种介质，空罐根据实际输入自动选择液体或气体 |
| 物品仓 | 27 个槽 | 同类竖向相邻物品仓合为连续槽位整体 |

这些方块可独立使用，也可参与机器构建；连接容量按段数累加，三个物品仓为81槽。储罐有内容时拒绝另一种介质；排空后可按下一次实际输入自动切换，模拟传输不会改变介质。已有内容不会因模式切换被清空或转换。双相反应釜会更新输入类型，并为适配配方的空输出罐选择介质；气液转换机遵循 GUI 选定方向。旧储罐及端口 ID 保留存档读取兼容，具有统一功能，拆除后掉落新版储罐或通用端口；创造栏及 JEI 展示统一后的方块。

仅同一竖向仓储列连接外观：上下相邻段的侧面边框和观察窗连续，列内部顶底面隐藏，整列只在两端保留端盖。并排的独立仓列保留完整边框；不同内容分成独立列的储罐也不误连。液位按整列实际总量自底向上显示，段间无空隙，只绘制真正的液面与列底面；从任意段装入液体都不会出现悬空液块。显示计算不移动库存，容量与多方块独立列计数保持原规则。储罐窗口显示实际液体纹理；气体默认使用水的动态纹理，氧气为天蓝色（#87CEEB）、氢气为白色（#FFFFFF），储罐、GUI与JEI保持一致。不依赖安装其他模组。

在机器内，物品仓及储罐只负责存储，直接管道能力关闭，输入输出由竖向相邻的对应通用端口负责。扳手只设置端口模式；端口只能连接一列对应仓库，并访问这一列的实际库存。输入仓与输出仓必须独立，共用或不同通道连接同一列会拒绝构建。同一通道可以包含多列，机器按每段27槽汇总库存及分页，相同仓库列的多个同模式端口不会重复计数。配方会搜索物品仓中的原料，实际消耗物品仓库存；液体/气体配方会利用储罐容量。缓存内容保存在各实际方块，不复制到控制器。

独立缓存右键打开缓存 GUI；成型机器中的缓存 **Shift 右键**打开缓存专用 GUI。物品仓可切换**小（27槽）、大（54槽）**视图，分别独立翻页；只改变每页展示数量，不增加或移除仓库容量。尺寸偏好保存到方块；服务端切换时保留鼠标携带物品及当前页附近的位置，旧81槽视图偏好自动迁移为54槽，大视图会自动适应当前窗口，鼠标点击、拖动同步缩放，不修改全局 GUI 设置。储罐界面显示实际介质、总量、总容量和段数；潜行使用流体容器可装入或取出液体。

拆分连接会保留各幸存方块本身的数据，重新连接后重新汇总；破坏物品仓时掉落被破坏段的物品，罐被破坏时只丢失该段介质。机器解体后，幸存缓存仍可独立使用。

## 五级管道

| 等级 | 物品/秒 | 流体 mB/秒 | 气体 mB/秒 |
| --- | ---: | ---: | ---: |
| 1 | 4 | 4,000 | 4,000 |
| 2 | 16 | 16,000 | 16,000 |
| 3 | 64 | 64,000 | 64,000 |
| 4 | 128 | 128,000 | 128,000 |
| 5 | 256 | 256,000 | 256,000 |

管道采用类似通用机械的**六面自动连接网络**，连接同类管道及兼容的机器接口、储罐或物品仓。模型和贴图随连接方向变化，支持转弯、分支和环路；物品、流体、气体三类网络互不连通。原创 **8×8** 工业像素材质采用深色轮廓、金属边框、等级色轨和介质内芯：物品为金色，流体为蓝色，气体为浅青色。两个相对端连接且没有分支时使用整段直管，连续纵向色轨沿 X／Y／Z 方向旋转；端点、转角和分支才显示方形接点，不在每格直管中央重复方块图案。背包和放置模型共用同一套类型图案。原生逐像素绘制，不从大图缩小。端面操作参考[通用机械 Configurator 官方说明](https://wiki.aidancbrady.com/wiki/Configurator)。

流体、气体管道每段均有 **1000 mB 实体缓存**，五个等级的容量相同，传输速率仍按等级区分。出口堵塞时缓存暂存资源，恢复后按速率输送；内容保存到存档并同步客户端，不混合不同液体或气体。缓存不会把资源送回注入它的端面。

管道默认只显示统一的 Shift 提示；**按住 Shift** 展开用途、等级、传输介质、最大速率、单段缓存、网络限制和四种端面配置。五级名称为基础、强化、高级、精英、终极，速率放在详情中。

**抽入／抽出接头只比管身大一圈**：管身横截面为 6×6 像素，金属套环为 8×8 像素。抽入用靠内的蓝色环，抽出用靠外的橙色环；普通连接保持细管身，断开端收起支臂。六个方向共用 Minecraft 模型旋转，扳手切换时同步更新外观与碰撞范围。移除原来的立体箭头、阶梯和扩口造型。

手持机械扳手，**Shift 右键对应支臂**，依次切换 **普通 → 拉取 → 推送 → 断开**；普通右键查看端面状态。点击中央方块时使用实际点击的面。

| 端面 | 行为 |
| --- | --- |
| 普通 | 默认模式，允许相邻设备主动输入，也向可接收的目标输送；不会主动抽取 |
| 拉取 | 主动从相邻容器或机器输出口抽取资源 |
| 推送 | 向相邻容器或机器输入口输送，拒绝外部输入 |
| 断开 | 隐藏连接支臂，禁止通过这一面传输；管道间只要一侧断开就不连接 |

例如 **机器输出口 → 管道 → 管道 → 储罐/输入口**，将管道靠近源容器的端面设成**拉取**，目标端保持普通或设成推送。可用分支先均分，整数余数轮换给各出口；满仓、不兼容或低速分支用不完的份额继续分配给其他可用出口。抽入面和源物品槽轮换，避免固定优先级导致长期饥饿。同一竖向缓存整体的多个端口只计算一次容量，不同仓库列独立参与分配。

同类五级管道可混接，每次输送计入路径所有管道的共享预算，速度受路径最慢段限制，分支不能复制主干吞吐。模拟与执行使用同一分配计划，模拟不会推进轮换位置。仅遍历已加载区块，单次最多搜索 1024 段；环路通过访问去重处理。正常输送直接提交到目标；若第三方接口实际拒收且源接口拒绝退回，暂存并保存余量，下次优先重试，暂存未清空前不继续抽取。拆除管道时暂存物品掉落。端面、轮换位置及异常暂存保存到 NBT。物品颜色过滤和可见物品包动画尚未实现。

物品使用 Forge `ITEM_HANDLER`，流体使用 Forge `FLUID_HANDLER`。Forge 本身没有通用气体接口，因此本模组提供独立 `GasCapabilities.GAS` / `IGasHandler`，气体使用命名空间 ID（例如 `alone_mechanical:hydrogen`）。其他模组气体需要对应适配器才能接入。

## 涡轮发电机与蒸汽

涡轮发电机使用**工业核心＋正上方涡轮组件**，结构保持横向长方体，至少放置一个涡轮转子、一个能量矩阵，以及一列接在**输入1**通用端口上的气体储罐。所有转子必须和能量矩阵处于同一条 X 轴或 Z 轴线上；工程锤会在轴线不一致时直接提示原因。每个转子每 tick 产生 **250 FE**，消耗 **50 mB `alone_mechanical:steam`**，转子数量同时线性增加输出和蒸汽消耗。蒸汽在气体界面使用白色半透明的动态水纹理渲染，储罐、机器 GUI 和 JEI 使用同一套流体渲染逻辑。

涡轮的发电与蒸汽参数可在配置中调整：`turbineFEPerRotor` 和 `turbineSteamPerRotor`。所有转子必须在同一高度、同一条水平轴线上连续连接到能量矩阵，中间不能隔空气、外壳或核心。能量矩阵对外提供只输出的 FE 接口，可紧贴电网核心提取电力；没有足够蒸汽或电池已满时，机器暂停本 tick，保留蒸汽。GUI 显示转子数量、总耗汽和总发电量。

## 开发检查工具：JEI 与 Jade

开发运行时加入 JEI 15.20.0.105 和 [Jade 11.9.4（Forge 1.20.1）](https://www.curseforge.com/minecraft/mc-mods/jade/files/5493390)，仅供测试，不内置到发布 jar，也不作为生存科技材料依赖。JEI 保留可选客户端集成，Jade 用于查看指向方块的信息。粉碎机、电弧炉、合金冶炼机及三相分离器分类显示输入、输出、耗时和基础耗能；粉碎核心、熔炼核心、合金组件、分解组件可用于查询对应配方与结构说明。电弧炉分类包括当前全部熔炼配方，配方重载后由 JEI 重新注册。空粉碎机分类没有加工配方时，JEI 仍可搜索已注册物品；不会补入测试配方。

客户端测试：服务器测试退出后运行 `./tools/prepare_jei_test_world.ps1` 准备独立测试存档，再执行 `./gradlew.bat --offline -PjeiSmokeTest runClient`。自动打开该存档，检查粉碎机、电弧炉与合金冶炼机分类、核心用途入口、当前配方布局和 Jade 加载状态；成功日志包含 `JEI SMOKE TEST PASSED`。服务端 GameTest 使用独立 `alone_mechanical_test` 命名空间中的测试探针验证其他加工功能；这些资源不进入发布 jar 或普通开发客户端。同时验证正式加工内容为三条粗金属粉碎、一条煤/木炭制碳和一条炼钢配方和一条水电解配方，以及双倍产物容量不足保护、空配方列表、外部熔炼兼容、仓库堆叠、上下端口、通道冲突及分页同步。

## 开发与验证

机器现支持分阶段生存制造：手工起步→钢与机械→电解液工业→高级能源→末地工业。初、中、高级电池使用对应电解液灌注空壳制成；高功率、长续航变体继续灌注成品高级电池。完整工序、阶段设备及参数见[机器制造与电池](docs/machine-manufacturing.md)。

初始铀矿现已自然生成于主世界Y=-64～64，丰度定位介于普通群系的铁矿与金矿之间；支持普通 / 深层两种矿石，旧存档需探索新生成区块。参数与数据包覆盖说明见[铀矿自然生成](docs/uranium-worldgen.md)。

```powershell
./gradlew.bat --offline build
./gradlew.bat --offline runGameTestServer
./gradlew.bat runClient
./tools/generate_resources.ps1
./tools/generate_test_templates.ps1
./tools/preview_pipe_models.ps1
```

离线命令需要已缓存的依赖。资源生成脚本是可重复执行的；修改资源前可选择直接编辑 JSON，或修改脚本后重新生成。测试源码和结构模板在 `src/gametest`，不进入发布 jar。

扩展机器的方法、配方格式和代码入口见 [docs/architecture.md](docs/architecture.md)。

核心与组件搭配、锻压配方入口、三种同介质分解及旧核心迁移见 [docs/machine-components.md](docs/machine-components.md)。

独立多方块电池的组装、三种充放电模式与电网流量说明见 [docs/energy-storage-matrix.md](docs/energy-storage-matrix.md)。

无额外数量上限的升级、工程锤快速重检、工程护目镜俯瞰与自由相机见 [docs/engineering-goggles.md](docs/engineering-goggles.md)。

工业核心的塑形组件与灌注组件分别处理物品→物品、物品+流体/气体→物品。现有导线、齿轮、分级电池、变体二次处理与维度灌注配方；仓储规则与数据包格式见 [docs/industrial-processing.md](docs/industrial-processing.md)，阶段制造见[制造与电池](docs/machine-manufacturing.md)。

涡轮转子采用带轮毂、八片扇叶和支架的风扇模型，自动对齐水平主轴。运行时整机实际每消耗50 mB/t蒸汽对应60 RPM，显示转速最高600 RPM；缺汽、满电或解体立即停止。外观转速不改变发电与耗汽参数。

管理员可使用 `/AloneMechanical build +结构` 快速生成并尝试成型机器；结构名包括 `crusher`、`arc_furnace`、`forging_press`、`forming_machine`、`infuser`、`alloy_smelter`、`reaction`、`separator`、`converter`、`boiler`、`turbine`、`slaughterhouse`、`breeding_tower`、`harvest_tower` 和 `repeller_tower`。也接受不带 `+` 的写法，并提供命令补全。扇叶正面投影固定为 **3×3 方块**，教程书的“机器搭建示例”章节逐项展示这些结构的核心、组件、仓储和端口布局。

统一核心说明：所有加工、范围、锅炉、涡轮和核反应堆多方块共用工业核心。核心位置可以偏离中点，供电桩与范围机器按实际核心位置判定；控制器仍须位于外表面。原其他机器核心保留注册 ID 并改为对应组件，旧结构需补放工业核心、将机型组件放在其正上方，再用工程锤重新成型。单方块发电机、电动泵、独立储能矩阵和电网节点沿用各自结构规则。

三种处理塔已加入：蒸馏组件、冷凝组件、交换组件均搭配工业核心。最小5×5×7，底面和边框为外壳；蒸馏/冷凝开顶，交换封顶并用完整隔层分为上下空间。通用端口直接连内部缓存，不放储罐。容积决定缓存和批量，右键GUI滑块调每批1–100%容积，实际耗能随批量增加。完整搭建、默认配方和指令示例见 [处理塔文档](docs/process-towers.md) 与游戏内教程。

硫酸工业产线：煤/木炭＋水→硫；硫＋氧气→SO₂；SO₂＋氧气→SO₃；SO₃＋蒸汽→硫酸气体；气液转换机液化→液态硫酸。首段仅产硫；已补齐物品、气体、流体、五段配方、JEI 与教程。详见 [硫酸产线](docs/sulfuric-acid-line.md)。另有开口式分离塔，工业核心＋空气分离组件，GUI开启并供电后从环境空气产出氮气和氧气；指令为 /AloneMechanical build +air_separation_tower。
